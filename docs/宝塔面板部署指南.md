# 宝塔面板部署指南（PHP 版 + MySQL）

本文针对**宝塔面板（BaoTa / aaPanel）**环境。宝塔是纯 Web 运维面板，
和小米路由器式的命令行部署差别很大，因此单列一篇。

---

## 零、先决定用哪种数据库

| | SQLite（默认） | MySQL |
|---|---|---|
| 依赖 | 无（PHP 自带 pdo_sqlite） | 需 MySQL/MariaDB 服务 |
| 与 Python 版共库 | ✅ 可以，两版可互相接管 | ❌ **不可以** |
| 备份 | 拷 `users.db` 一个文件 | 面板里导出，或 mysqldump |
| 适用 | 单机、轻量、想和 Python 版共用数据 | 多机、已有 MySQL、只跑 PHP 版 |

> **重要**：`users.db` 是 Python 版唯一支持的存储。一旦 PHP 版切到 MySQL，
> **两版就不能再共用同一份数据了**。如果你只部署 PHP 版，MySQL 是更好的选择。

宝塔里通常已经有 MySQL，所以**只跑 PHP 版**的场景建议直接用 MySQL。

---

## 零·前置：PHP 版本必须是 8.0 以上（否则整站白屏）

**这是部署失败的第一大原因，先确认它。**

症状 —— 访问站点只看到一行：

```
Fatal error: Dynamic class names are not allowed in compile-time ::class fetch
in /www/wwwroot/你的站点/public/index.php on line 215
```

原因：PHP 版的代码用了 PHP 8.0 的**语法**（`$obj::class`、非捕获式
`catch (Throwable)`、联合类型参数）。这类错误发生在**编译期** ——
整个文件编译不过，所以文件里任何运行时检查都不会执行。
那句报错是 PHP 7 独有的，看到它就说明：**服务器跑的是 PHP 7.x**。

处理 ——

| 环境 | 操作 |
|---|---|
| 宝塔面板 | 网站 → 你的站点 → 设置 → **PHP 版本** 选 `8.0` / `8.1` / `8.2` → 保存 |
| 还没装 PHP 8 | 软件商店 → 安装 PHP 8.x；装完回上一步切换 |
| 命令行 | `php -v` 应显示 8.0 以上；`php -m` 应有 `pdo_mysql`/`pdo_sqlite`、`curl`、`openssl`、`mbstring`、`fileinfo`、`sockets` |

> 1.0.2 起，PHP 版本不对时入口会**先打印一段可读提示**（直接告诉你当前版本、
> 该去面板哪里改），而不再抛上面那句看不懂的 Fatal error。
> 这段提示由 `tools/verify_php_compat.py` 机械守住 —— 它会真的用 PHP 7.4
> 容器跑一遍入口文件，防止谁日后往入口里写一个 PHP 8 语法糖又把整站弄白。

**为什么不把代码降到兼容 PHP 7.4**：那样要改掉全站的 `str_starts_with`、
联合类型、构造器提升、非捕获 catch 等几十处，测试矩阵翻倍；而 PHP 7.4
已于 **2022-11 停止安全支持**，降级适配等于把安全债留在生产环境里。

## 零·一、目录怎么摆（先看这个，否则装完必白屏）

入口原先硬编码 `dirname(__DIR__, 2)`，只在**仓库原样布局**下成立。宝塔上更常见的
做法是把 `php/public` 的内容直接丢到站点根 —— 那样会退到仓库根的上一级，报出：

```
Warning: require(/www/wwwroot/php/src/helpers.php): Failed to open stream
Fatal error: Uncaught Error: Failed opening required ...
```

（真实现场。）现在入口会自动探测下面 **4 种布局**，都能跑：

| 布局 | docroot（宝塔「运行目录」） | 代码位置 | 数据根 |
|---|---|---|---|
| A 标准（**推荐**） | `<站点根>/php/public` | `<站点根>/php/src` | `<站点根>` |
| B 扁平 | `<站点根>/public` | `<站点根>/src` | `<站点根>` |
| C 扁平 | `<站点根>/public` | `<站点根>/php/src` | `<站点根>` |
| D 全平铺 | `<站点根>` | `<站点根>/src` | `<站点根>` |

**推荐照 A 摆**，最省事：

```
/www/wwwroot/你的域名/          ← 整个仓库都传到这里（不是只传 public）
├── php/
│   ├── public/                 ← 运行目录选 /php/public
│   ├── src/  scripts/  templates/  routes.php
├── data/                       ← 需要可写
├── store/  work/  cache/       ← 需要可写
├── users.db                    ← SQLite 时
└── config.json
```

两个**最容易漏**的东西（都不在 `public/` 里，只传 public 就一定会出问题）：

1. **`php/routes.php`** —— 漏了会看到 `找不到路由定义文件 routes.php`（有明确提示）。
2. **`data/`、`store/`、`work/`、`cache/` 四个可写目录** —— 宝塔：网站 → 设置 → 目录权限。

一个都认不出来时，程序不会再抛 PHP fatal，而是给一页**可照做**的说明：
它会列出实际找过哪些路径、当前 docroot、期望结构、以及两条修法。

## 零·一·五、`putenv` 必须放行 —— 不放行则 MySQL 安装 500

**真实现场**（PHP 8.1 + 宝塔，向导第 2 步选 MySQL 提交后）：

```
Uncaught Error: Call to undefined function putenv()
in public/install.php on line 389
```

宝塔默认把 `putenv` 写进 `disable_functions`。被禁的函数在 PHP 里等同
「未定义」，**直接调用就是致命错误**，而向导原先无条件用 `putenv` 让本次请求
立刻用上新配置 → 必 500。现版本已改为 `function_exists('putenv')` 探测、
被禁时跳过（配置已落盘 `config.local.json`，下次请求自然会读到），安装不再中断。

** 尽管如此仍建议放行 `putenv`**：宝塔 → 软件商店 → PHP 8.1 → 设置 →
禁用函数，删掉 `putenv`。验证工具：

```
python3 tools/verify_bt_disable_functions.py
# 环境变量 KWRT_TEST_MYSQL_* 给了就顺带跑 MySQL 分支
```

它用 `php -d disable_functions=putenv,proc_open,exec,shell_exec,symlink,popen`
起一个与宝塔同构的环境，把向导从头走到尾（7 项断言）。

## 零·二、两种构建后端怎么选（php版已同时支持）

PHP 版**同时支持**本地实编与远端 GitHub Actions，后台「构建 → 构建后端」切换。

| | 本地（local） | 远端（github） |
|---|---|---|
| 需要 `exec` 可用 | **是**（起构建子进程） | **是**（起轮询子进程） |
| 需要磁盘 | ~2.6 GB/次 | 几乎不占 |
| 需要 CPU/内存 | 高（`make` 是 CPU/IO 密集） | 低 |
| 构建期是否占本站带宽 | 是 | 只占产物回传那一段 |
| 前置条件 | 装好 `tar`/`zstd`/`make` | 填 `gh.repo` / `gh.token` / `gh.workflow` / `gh.ref`，并打开 `gh.enabled` |

**关键点（两条都是实测踩出来的）**：

1. **`exec` 两种后端都需要**。别以为切到远端就不用 `exec` 了 —— 派发之后要有人
   轮询构建状态（最长 90 分钟），那个人就是 `Builder::pump()` 起的 worker 进程。
   宝塔默认把 `exec`/`proc_open` 放进 `disable_functions`，症状是提交后立刻
   「构建进程启动失败」，任务详情里有明确提示。到
   **软件商店 → PHP → 设置 → 禁用函数** 里删掉 `exec` 即可（也可用面板的
   「计划任务」每分钟跑 `php php/scripts/reap.php` 兜底，但派发仍需 `exec`）。

2. **多队列**。`gh.queues` 填 JSON 数组即可配多条队列（每项
   `{"name","repo","token","workflow","ref","enabled"}`），派发时按轮转挑选；
   为空则用 `gh.repo`/`gh.token` 合成单队列（老配置无需改动）。

3. **产物回传**。`gh.mirror_artifacts=开` 时会把 GitHub 产物拉回本站
   `store/`，于是「限时下载链接」机制对两种后端**一致生效**；
   关掉则直接给 GitHub 产物地址（有效期由 GitHub 保留策略决定）。
   `gh.mirror_timeout` 是回传总时限，跨国带宽慢时放宽到 7200。

4. **需要 `zip` 或 `phar` 扩展**（产物回传解压用）。`zip` 缺失时会自动用
   `phar` 兜底；两者都没有才会报错 —— 报错信息里给了宝塔的安装路径。

## 一、安装面板环境

1. 宝塔面板 → **软件商店**，安装：
   - **Nginx**（或 Apache，本文以 Nginx 为例）
   - **MySQL 5.7 / 8.0**（或 MariaDB 10.4+）
   - **PHP 8.0 / 8.1 / 8.2**
2. PHP 设置里确认已装扩展（软件商店 → PHP → 设置 → 安装扩展）：
   - **必需**：`pdo_mysql`、`pdo_sqlite`、`curl`、`openssl`、`mbstring`、`json`、`zlib`、`sockets`、`fileinfo`
   - 推荐：`opcache`（明显提速）
3. PHP → **禁用函数**里确认**没有**禁用：`proc_open`、`exec`、`shell_exec`、`putenv`
   （PHP 版构建固件需要 spawn 子进程。若必须禁用，构建功能会失效但站点其余部分正常）

## 二、上传代码

1. **网站** → 添加站点：
   - 域名：你的域名
   - PHP 版本：8.0+
   - **数据库**：勾选「MySQL」，库名如 `kwrt`，记下自动生成的口令
   - 不要勾选「创建 FTP」
2. **根目录设置为 `<站点目录>/php/public`** —— 这是最容易错的一步。
   把根目录指到仓库根，整个源码目录（含密钥、数据库文件）都会变成可下载的静态资源。
   宝塔：站点 → 设置 → 网站目录 → 运行目录改为 `/php/public`。

   > 若面板不允许把运行目录设到子目录，就改用下面的 Nginx 伪静态把请求转发过去。

3. 把仓库内容上传到站点目录（例如 `/www/wwwroot/kwrt`），保证存在
   `/www/wwwroot/kwrt/php/public/index.php`。

4. **目录权限**：宝塔 → 网站 → 设置 → 目录权限，把属主设为 `www`，权限 `755`；
   并确保这些目录可写（PHP 要往里面写构建产物与数据库）：
   ```
   users.db（若用 SQLite）
   store/   work/   cache/   data/
   ```
   宝塔的「防跨站攻击(open_basedir)」若开启，需确认**没有**把 `<站点目录>` 的上级排除掉，
   否则 PHP 读写上级目录会报 `open_basedir restriction in effect`。

## 三、配置数据库连接

宝塔不允许你改 `/etc/my.cnf` 之外的 MySQL 配置，所以**推荐用环境变量**方式配置，
不把口令写进版本库里的文件。

### 3.1 方式 A：PHP-FPM 环境变量（推荐）

宝塔 → 软件商店 → **PHP 8.x → 设置 → 配置修改**，或直接编辑
`/www/server/php/80/etc/php-fpm.d/www.conf`，在 `[www]` 段加入：

```ini
env[KWRT_DB_DRIVER] = mysql
env[KWRT_MYSQL_HOST] = 127.0.0.1
env[KWRT_MYSQL_PORT] = 3306
env[KWRT_MYSQL_DB]   = kwrt
env[KWRT_MYSQL_USER] = kwrt
env[KWRT_MYSQL_PASS] = 面板里生成的口令
```

保存后**重载 PHP-FPM**（宝塔 → PHP → 重载配置），否则不生效。
环境变量方式比 `config.local.json` 更安全：不会被误提交、也不会被 Web 读到。

### 3.2 方式 B：`config.local.json`（该文件已在 .gitignore 内）

在站点目录建 `config.local.json`：

```json
{
  "db": {
    "driver": "mysql",
    "mysql": {
      "host": "127.0.0.1",
      "port": 3306,
      "dbname": "kwrt",
      "user": "kwrt",
      "pass": "你在面板里设的口令",
      "prefix": ""
    }
  }
}
```

### 3.3 校验连接

浏览器访问 `https://你的域名/healthz`，看到 `"ok":true` 即通。
若报错，PHP 版会给出**可照抄的**提示（这是刻意做的）：

| 报错 | 含义 | 处理 |
|---|---|---|
| `MySQL 里没有数据库 \`kwrt\`` | 库没建 | 宝塔 → 数据库 → 添加数据库，或按提示执行 `CREATE DATABASE` |
| `MySQL 账号或口令不对` | 凭据错 | 宝塔 → 数据库 → 改口令，同步改环境变量 |
| 数据目录不可写 | 权限问题 | 见 §二.4，属主设 `www`，检查 open_basedir |
| `could not find driver` | 缺扩展 | 装 `pdo_mysql` |

## 四、Nginx 伪静态（关键）

宝塔站点 → 设置 → **伪静态**，粘贴：

```nginx
location / {
    try_files $uri $uri/ /index.php?$query_string;
}
```

**必须有一条**，否则所有非真实文件的路径（`/packages/`、`/api/v1/site`、
`/sitemap.xml` 等）都会被 Nginx 直接 404 —— 这是宝塔部署最常见的「整站打不开」。

另外建议（宝塔 → 站点 → 设置 → 配置文件）加上静态资源与安全头：

```nginx
# 静态资源长缓存（文件名带 ?v= 版本号，可放心长缓存）
location ~* ^/(assets|static)/ {
    expires 30d;
    add_header Cache-Control "public, max-age=2592000";
}

# 不要把源码与数据暴露成静态文件（双保险，运行目录已指向 php/public）
location ~* /(php/src|php/scripts|data|cache|work)/ { deny all; }
location ~* \.(db|sqlite|sqlite3|env|json\.local)$ { deny all; }

client_max_body_size 210m;   # 上传自制文件包上限 200MB，留点余量
```

`client_max_body_size` 必须放宽：默认 1MB，上传固件包会直接 413。

## 五、打开安装向导（推荐）

**不用碰终端。** 浏览器访问：

```
https://你的域名/install.php
```

向导四步走完，每一步失败都会告诉你**具体哪一项、怎么修**：

| 步骤 | 做什么 |
|---|---|
| ① 环境检查 | PHP 版本、扩展、目录可写、构建所需函数是否被禁、磁盘余量 |
| ② 数据库 | 选 SQLite（零配置）或 MySQL（填主机/端口/库名/账号/口令），带「测试连接并初始化」 |
| ③ 管理员 | 建第一个管理员，口令 ≥8 位、两次确认 |
| ④ 站点设置 | 站点名、绑定域名、额外 Host、强制 HTTPS（都可跳过） |

装完向导会：

- 在 `data/install.lock` 写一条安装记录，**从此拒绝再运行**；
- 在 `data/INITIAL_ADMIN.txt`（权限 `0600`）留一份凭据给你；
- 提示你删除 `php/public/install.php` 或保留锁文件。

> **上面第 ③ 步的数据库报错要分清三种**，向导现在会分开说：
> - `Unknown database` → 库没建，去面板建库（字符集 utf8mb4）
> - `对库 xxx 没有授权` → 库有了但账号没被授权（新建库最容易踩），面板里给权限
> - `账号或口令不对` → 才是真的凭据错

### 向导的三条安全设计（知道一下没坏处）

1. 装完写 `data/install.lock`，向导自身拒绝运行 —— 否则谁访问 `/install.php`
   都能重建管理员，等于后门。
2. **若库连通且已存在管理员，即使没有锁文件也一律拦截** ——
   只靠锁文件挡不住「删掉锁文件再来一次」这种接管手法。
   确有重装需求时，需在服务器上放一个空文件 `data/install.allow`（证明你有文件系统权限），
   用完自动删除。
3. 所有写操作都要 CSRF token；数据库口令在页面上永不回显。

### 没有浏览器 / 想走命令行

```bash
cd /www/wwwroot/kwrt
php php/scripts/init_admin.php
```

会打印随机管理员口令，也可先设 `KWRT_ADMIN_PASSWORD` 指定。
注意 CLI 下要带上与 Web 一致的数据库变量，否则 CLI 连 SQLite、Web 连 MySQL：

```bash
KWRT_DB_DRIVER=mysql KWRT_MYSQL_DB=kwrt KWRT_MYSQL_USER=kwrt KWRT_MYSQL_PASS='口令' \
  php php/scripts/init_admin.php
```

## 六、接管已有 SQLite 数据（可选）

如果你之前用 SQLite 跑过，想把数据搬到 MySQL：

```bash
# 1) 按上面的方式让 CLI 连上 MySQL（保证表已建好）
# 2) 导出 SQLite 全表为 SQL
for t in users settings builds proposals jobs admin_logs bans dl_tokens \
         sponsor_claims pay_orders email_verifications email_send_log \
         refund_requests rate_limits login_fails captchas app_secrets; do
  echo "-- $t"
  sqlite3 users.db ".mode insert $t" "SELECT * FROM $t;"
done > /tmp/dump.sql

# 3) 导入 MySQL（把 INSERT INTO 加上反引号，避免 key/value 保留字踩坑）
sed -i 's/INSERT INTO \([a-z_]*\)/INSERT INTO `\1`/' /tmp/dump.sql
mysql -h127.0.0.1 -ukwrt -p'口令' kwrt < /tmp/dump.sql
```

导入后到后台核对用户数、订单数、设置项即可。

## 六·五、单实例部署要点（本项目的目标形态）

PHP 版队列的互斥靠 `jobs` 表做（`UPDATE … WHERE status='queued'` 抢槽），
所以**单实例是它最稳的形态** —— 不依赖任何进程内状态。

### 并发数：单实例建议 1（最多 2）

后台「构建设置 → 最大并发」按机器定，别照抄多机数值：

| 机器 | 建议最大并发 | 依据 |
|---|---|---|
| 2 核 / 2 GB | **1** | 单次构建 `work/` 约 2 GB，`make` 吃满 CPU |
| 4 核 / 4 GB | **1～2** | 每次构建峰值磁盘 ~2.6 GB（worker 开跑前会自检，不够就直接判失败） |
| 8 核 / 8 GB+ | 2～3 | 再多收益递减，且 `store/` 增长很快 |

> 并发数**调大不会更快**：瓶颈是 `make` 的 CPU 与磁盘 IO。宁可排队。

### 不需要额外的「僵尸任务定时器」

这是刻意设计的：`Builder::pump()` 在**每次提交构建时**先调用 `reap()` 回收
失联的 worker。也就是说 ——

- 有僵尸占着槽位时，下一次提交会**先把它清掉再抢槽**，用户不会被卡住；
- 空闲时没人提交，也就没人需要槽位，不必白白轮询数据库。

因此**不需要**给它单独配 cron/systemd timer。若你仍想要一层保险
（例如希望「僵尸在后台页面里尽快显示为失败」而不是等到下次提交），
可以加一条低频 cron：

```bash
# 每 10 分钟跑一次；注意 CLI 下要带与 Web 一致的数据库变量
*/10 * * * * cd /www/wwwroot/kwrt && \
  KWRT_DB_DRIVER=mysql KWRT_MYSQL_DB=kwrt KWRT_MYSQL_USER=kwrt KWRT_MYSQL_PASS='口令' \
  php php/scripts/reap.php >/dev/null 2>&1
```

僵尸判定阈值默认 **3 小时**（＝ Engine 里 `make` 上限 2 小时 + 1 小时余量），
慢机器上可放宽：`KWRT_STALE_RUNNING_SECONDS=14400`（4 小时）。
**不要设得比最长构建时间还短** —— 那会把正常构建误杀。

### `exec` 必须是可用的（单实例最常踩的坑）

PHP 版是**本地构建**，worker 由 `exec('nohup php build-worker.php … &')` 拉起。
宝塔默认会在 `disable_functions` 里禁用 `exec`/`proc_open`：

- 症状：提交构建后**立刻**提示「构建进程启动失败」，
  任务详情写明「exec / proc_open / shell_exec 全部被禁用」。
- 处理：软件商店 → PHP → 设置 → **禁用函数**，删掉 `exec` 与 `proc_open`，重载 PHP-FPM。
- 不愿意放开 `exec`：改用后台「GitHub 构建 → 构建队列」的**远端 GitHub Actions 后端**，
  本地不需要执行任何子进程（但仍需要 `curl` 出网）。

> 1.0.2 之前这里是个**静默故障**：`@exec` 吞掉一切错误，向用户报「已开始构建」，
> 而任务永远停在 `running`、把并发槽位吃光，最终队列彻底不动。
> 现已改为启动前探测 + 如实报错 + 僵尸自动回收。

## 七、构建功能（宝塔额外注意事项）

PHP 版是**本地构建**：它会在服务器上解压 OpenWrt ImageBuilder 并执行 `make`。
宝塔环境需要额外确认：

1. **磁盘**：单次构建需要 **≥3 GB** 临时空间（`work/` 目录）。宝塔 → 首页看磁盘余量。
2. **下载源**：构建要访问 `downloads.openwrt.org` 与 `dl.openwrt.ai`。
   国内机房若慢或不通，在后台「GitHub 构建 → 构建队列」改用远端 GitHub Actions，
   或给服务器配代理。
3. **超时**：
   - PHP：宝塔 → PHP → 配置修改，把 `max_execution_time` 设为 `0`（不限）；
   - Nginx：`fastcgi_read_timeout 3600s;`
   - 否则构建跑一半被 FPM 掐断，表现为「一直排队」。
4. **构建超时保护**：后台「构建设置 → 构建超时」可设上限。
5. 生产建议：把 `work/`、`cache/` 放到独立的盘或大分区，避免构建把系统盘写满。

## 十·零、把 Python 版部署到宝塔（反向代理）—— 实测全流程

PHP 版是「把代码丢进站点目录让 nginx 跑 PHP」；**Python 版不是**：它是一个常驻
进程（uvicorn），nginx 只做反向代理。完整链路：

```
浏览器 → nginx(:80, server_name op.2016xlx.cn)
       → location ^~ / → proxy_pass http://127.0.0.1:8443
       → uvicorn app.main:app（systemd: kwrt.service）
```

### 步骤

1. **代码与虚拟环境**（`install.sh` 会做，也可手动）
   ```bash
   cd /root/kwrt-clone
   python3 -m venv .venv
   .venv/bin/pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
   ```
   国内环境务必带 `-i` 镜像，否则 pip 极易超时。

2. **systemd 常驻**（`scripts/kwrt.service` / `install.sh` 第 5 步）
   三个环境变量**必须显式给**，缺一个都会出问题：
   - `WorkingDirectory=` —— app 内部有按相对路径打开的文件，缺了会让「验证邮件」等链路在 systemd 下静默失效
   - `Environment=FORWARDED_ALLOW_IPS=`（**留空**）—— uvicorn 的 `proxy_headers` 默认开启、
     且默认信任 `127.0.0.1,::1`，而本机反代恰好就是这个来源，于是它会用 `X-Forwarded-For`
     改写 `request.client`，**把应用层的可信代理判定架空**（实测可让封禁被一个请求头绕过）
   - `EnvironmentFile=-/root/kwrt-clone/kwrt.env` —— `-` 前缀允许文件不存在

3. **宝塔建站 + 反向代理**（面板操作，或用 API）
   - 建站时 PHP 版本直接选**「纯静态」**（`version=00`）—— 反代不需要 PHP
   - 站点 → 反向代理 → 添加：目标 URL `http://127.0.0.1:8443`，**代理目录 `/`**
   - 用 `proxydir=/` 时宝塔会顺手把站点改成纯静态

4. **在应用里绑定域名**（**必须在建反代之前或同时做**）
   ```bash
   cd /root/kwrt-clone && .venv/bin/python -c \
     "import app.sitesettings as S; S.set_('site.domain','你的域名'); S.set_('site.trusted_hosts','你的域名')"
   ```
   应用有可信主机校验：`site.domain` 与 `site.trusted_hosts` **都为空**时
   `site.allow_any_host`（默认 True）放行一切；一旦绑了域名就只认它。
   **回环地址永远放行**（防自锁），所以绑完不会把自己关在外面。
   验证：`curl -H 'Host: 域名' http://127.0.0.1:8443/` → 200；
   `curl -H 'Host: evil.com' …` → **400**。

### ★ 三个实测踩到的坑

**坑 1：宝塔反代 API 的 `type` 必须传 1，否则写出一个 0 字节配置文件。**
`panelSite.py::SetProxy` 里生成配置的代码段**只在 `type == 1` 时执行**：

```python
if type == 1 and cache == 1: ng_proxy_cache += ng_proxy % (...)
if type == 1 and cache == 0: ng_proxy_cache += ng_proxy % (...)
public.writeFile(ng_proxyfile, ng_proxy_cache)     # 传 0 → 写了个空文件
```

症状极隐蔽：`CreateProxy` 返回 `{"status":true,"msg":"添加成功"}`，面板里反代条目
也在，`nginx -t` 也过 —— 但 vhost 里 `include .../proxy/<域名>/*.conf` 引到的是空文件，
于是**请求落到站点静态根**（看到宝塔的「恭喜，站点创建成功！」页），表现成「反代没生效」。
排查一条命令：`wc -c /www/server/panel/vhost/nginx/proxy/<域名>/*.conf`。

> 相关 API：`/site?action=CreateProxy`（参数 `sitename`/`proxyname`/`proxydir`/`proxysite`/
> `todomain`/`type`/`cache`/`subfilter`/`advanced`/`cachetime`）、`RemoveProxy`（`sitename`+`proxyname`）。
> `ModifyProxy` 会先读旧文件解析，文件是空的时候报「配置文件读取错误」。
> `proxyname` 长度必须 3~40 字节。

**坑 2：宝塔反代模板会覆盖应用的缓存头。**
模板默认塞进 `expires 1m`（静态后缀）与 `add_header Cache-Control no-cache`（其余），
实测把应用自己发的
`Cache-Control: public, max-age=31536000, immutable` **压成 `max-age=60`** ——
每次访问都要回源重拉全部 CSS/JS。
本项目应用侧（`app/netcfg.py` 的缓存头逻辑）已经按「带版本号的静态资源长缓存 +
HTML no-cache」发对了头，**反代只需原样透传**，因此要把模板里那段缓存指令删掉，
换成纯透传 + 长超时：

```nginx
location ^~ /
{
    proxy_pass http://127.0.0.1:8443;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_http_version 1.1;
    proxy_read_timeout 3600s;      # 固件下载/长轮询，默认 60s 会中途断开
    proxy_send_timeout 3600s;
    client_max_body_size 64m;      # 带附件的表单
}
```
⚠ **若日后在面板「反向代理」界面点保存，整段会被模板重新生成**并带回缓存规则，
需要重做本修改。

**坑 3：`__pycache__` 会让改过的代码不生效。**
替换 `app/*.py` 后要 `find app -name __pycache__ -type d -exec rm -rf {} +` 再重启，
否则可能仍加载旧字节码。

### 验证清单
```bash
systemctl is-active kwrt                      # active
curl -s http://127.0.0.1:8443/healthz         # {"ok":true,...}
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: 域名' http://127.0.0.1/healthz   # 200
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: 域名' http://127.0.0.1/login/    # 200
curl -s -o /dev/null -w '%{http_code}\n' http://域名/                                 # 200（经 CDN）
curl -s -D - -o /dev/null -H 'Host: 域名' http://127.0.0.1/assets/css/app.css | grep -i cache-control  # 应为应用发的值，非 max-age=60
```
另需确认 **uvicorn 的 8443 没有对外暴露**（`ss -lntp | grep 8443` 只应经 nginx 可达）。

## 十、与 Python 版的关系（务必知道）

| | Python 版 | PHP 版 |
|---|---|---|
| 数据库 | **仅 SQLite** | SQLite **或** MySQL |
| 共库 | 与 PHP(SQLite) 可共用 | 切到 MySQL 后**不再共库** |
| 口令哈希 | `pbkdf2_sha256$240000$盐$哈希` | 同格式、逐字节一致 |

因此：
- **想两版共库** → 两边都用 SQLite，PHP 不要开 MySQL。
- **只想用 PHP + MySQL** → 完全没问题，本文档就是这条路。
- **想从 SQLite 迁到 MySQL** → §六。
