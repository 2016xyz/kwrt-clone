## 二、真跑暴露的「假修复」：U-3 精确路径从未生效

上一轮我声称「dispatch 改用 `return_run_details=true` 取精确 run_id」。
**真跑发现它根本没起作用** —— 我把参数放进了 query string，GitHub 直接无视：

```bash
# 放 query：GitHub 忽略该参数，仍返回 204 空响应
curl -X POST ".../dispatches?return_run_details=true" -d '{"ref":"main",...}'
→ HTTP 204, body 空

# 放 body：才返回 200 + 精确 run_id
curl -X POST ".../dispatches" -d '{"ref":"main","inputs":{...},"return_run_details":true}'
→ HTTP 200
  {"workflow_run_id": 36103129259,
   "run_url": "https://api.github.com/repos/.../runs/36103129259",
   "html_url": "https://github.com/.../runs/36103129259"}
```

**修复**：参数改放请求体。实测取到精确 `workflow_run_id`。

**为什么这条只有真跑才能发现**：单测只验证了「拿到 run_id 能继续走」，
而启发式兜底（45 秒内 + 同分支 + 认领互斥）在单实例低并发下**总是能碰对**，
不会暴露精确路径其实一直是空转。

## 三、本轮新发现的漏洞（4 项，均已修复）

### 3.1 `_safe_extract` 符号链接前缀绕过 —— 真实越界写（中危）

| 项目 | 内容 |
|---|---|
| **类型** | 路径穿越（CWE-22） |
| **位置** | `app/builder.py:190`（原 `os.path.realpath(target).startswith(dest)`） |
| **描述** | 判定少了 `os.sep`。当 `dest=/a/user` 时，`/a/userX` 是它的**字符串前缀**而非子路径，于是「符号链接指向兄弟目录」能通过校验 |
| **实测** | 构造 tar：`link → ../userX`，再写 `link/escaped.txt` → **文件真的落到了 `dest` 之外**（`userX/escaped.txt`） |
| **修复** | 新增 `_inside(base, path)`（realpath + `os.path.commonpath`）统一判定；并对所有条目的最终落点加兜底校验 |
| **回归** | 12 例：6 类攻击全拦，4 类合法归档正常 |

复现与回归脚本：`tools/extract_regression.py`

```
用例                        被拦截   期望拦截   越界写出   判定
tar ../ 穿越                True    True      []        ✓
tar 绝对路径                 True    True      []        ✓
tar 符号链接前缀绕过            True    True      []        ✓
tar 符号链接 /etc            True    True      []        ✓
tar 硬链接越界                True    True      []        ✓
tar 设备文件                 True    True      []        ✓
zip ../ 穿越                True    True      []        ✓
zip 符号链接                 True    True      []        ✓
合法 tar.gz                 False   False     []        ✓
合法 多层目录                  False   False     []        ✓
合法 zip                    False   False     []        ✓
符号链接指向 dest 内            False   False     []        ✓
```

### 3.2 zip 解压「先落盘后校验」（中危）

| 项目 | 内容 |
|---|---|
| **位置** | `app/builder.py`（原 `unzip`/`7z` 解压后才遍历校验） |
| **描述** | 越界条目在被发现前**已经写入宿主文件系统**，校验只是「事后告知」 |
| **修复** | `.zip` 改用 `zipfile` **逐条预检**（路径段 + 符号链接属性位 `S_IFLNK`）后才 `extractall`；`.7z` 无 stdlib 支持，保留事后校验（并注明 7z 未安装时该格式不可用） |

### 3.3 `/store` 泄露中间态文件（低-中危）

| 项目 | 内容 |
|---|---|
| **位置** | `store_index` / `store_file` / 管理端产物清单 |
| **描述** | 回传过程中的 `.openwrt-…zip`（**半截压缩包**）与 `.openwrt-…zip.fp`（身份指纹）会被列进产物索引，且可被直接下载 |
| **实测** | 回传进行时 `GET /store/<hash>/` 会把半截包列为可下载文件 |
| **修复** | 三处统一过滤以 `.` 开头的文件；`store_file` 对隐藏名直接 404 |
| **实测（修复后）** | 目录索引 9 个产物、无隐藏项；直接取隐藏文件 → **404**；取正常产物 → 200 |

### 3.4 `register` / `resend_verify` 无限速（中危）

| 项目 | 内容 |
|---|---|
| **位置** | `POST /api/v1/register`、`POST /api/v1/resend_verify` |
| **描述** | 两者**完全没有来源限速**。实测可连续无限注册账号；`resend_verify` 只有「同账号 60 秒冷却」，遍历用户名即可持续触发发信 = **邮件轰炸** |
| **修复** | 新增通用滑动窗口限速 `rate_ok(bucket, key, limit, window)`（进程内、带容量上限）；register 限 5 次/小时/IP，resend_verify 限 5 次/10 分钟/IP |
| **实测（修复后）** | 两者均 5 次通过、**第 6 次起 429** |
