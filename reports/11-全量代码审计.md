## 三、修复后代码

### 3.1 构建队列：不再假成功、僵尸自动回收（`php/src/Builder.php`）

```php
/** 判定「僵尸任务」的时限（秒）。取 3 小时：Engine 里 make 的上限是 2 小时，留 1 小时余量。 */
private static function staleAfterSeconds(): int
{
    $env = getenv('KWRT_STALE_RUNNING_SECONDS');
    if (is_string($env) && $env !== '' && ctype_digit($env)) {
        return max(600, (int) $env);
    }
    return 3 * 3600;
}

/** 回收僵尸任务：长时间无更新的 running 任务判失败，归还并发槽位。幂等。 */
public static function reap(): int
{
    $cutoff = microtime(true) - self::staleAfterSeconds();
    $rows = Db::all(
        "SELECT request_hash FROM jobs "
        . "WHERE status='running' AND COALESCE(updated, created, 0) < ?", [$cutoff]);
    $n = 0;
    foreach ($rows as $r) {
        self::fail((string) $r['request_hash'],
            '构建进程已失联（超过 ' . intdiv(self::staleAfterSeconds(), 3600)
            . ' 小时没有进度更新）—— 通常是 worker 进程被中断。槽位已自动释放，可重新提交。');
        $n++;
    }
    return $n;
}

public static function pump(): array
{
    return Db::tx(function () {
        self::reap();                 // ★ 先回收僵尸，否则被占住的槽位永远回不来
        $running = (int) Db::val("SELECT COUNT(*) FROM jobs WHERE status='running'", [], 0);
        /* … 抢槽逻辑不变 … */
        if (!self::spawnWorker((string) $next['request_hash'])) {
            return [false, '构建进程启动失败，详见任务详情', 0];   // ★ 不再无条件报成功
        }
        return [true, '已开始构建', 0];
    });
}

/** exec / proc_open 被 disable_functions 禁用是宝塔的默认形态，必须先探测。 */
private static function canSpawn(): bool
{
    $disabled = array_map('trim', explode(',', (string) ini_get('disable_functions')));
    foreach (['exec', 'proc_open', 'shell_exec'] as $fn) {
        if (function_exists($fn) && !in_array($fn, $disabled, true)) {
            return true;
        }
    }
    return false;
}

private static function spawnWorker(string $hash): bool
{
    if (!self::canSpawn()) {
        self::fail($hash,
            "无法启动构建进程：PHP 的 exec / proc_open / shell_exec 全部被禁用。\n"
            . "宝塔面板：软件商店 → PHP → 设置 → 禁用函数，删掉 exec 与 proc_open，"
            . "然后重载 PHP-FPM。或改用「远端 GitHub 构建后端」（不需要本地 exec）。");
        return false;
    }
    /* … PHP_BINARY / worker 脚本存在性检查（各自 fail 并 return false）… */
    $out = []; $rc = -1;
    @exec($cmd, $out, $rc);
    if ($rc !== 0) {                     // 非 0 = 连进程都没发出去
        self::fail($hash, "启动构建进程失败（shell 返回 {$rc}）。请检查 PHP 的执行权限与禁用函数。");
        return false;
    }
    return true;
}
```

## 六、需要我补充的信息

1. **部署形态**：单实例还是多机？PHP 版队列靠 DB 表做互斥，多机安全；但 `reap()` 的阈值（3 小时）在**慢机器**上是否需要调大？
2. **是否已确认要开「远端 GitHub 构建后端」**？若开，`exec` 被禁用就不再是问题，`reap()` 的阈值应改为对 GitHub run 的超时判定。
3. **僵尸回收阈值是否要做成后台设置项**（`build.stale_after_hours`）？目前是常量 + 环境变量，未进 schema（避免动 schema 与生成物）。答案会改变实现。

## 七、建议增加的测试用例

1. `KWRT_STALE_RUNNING_SECONDS=600` + 一条 11 分钟前的 `running` → 必须被回收；**且**一条 9 分钟前的**不得**被回收（正向反例）。
2. 多进程并发 `pump()`（`php -S` 不好测，用 10 个并发 CLI `pump()`）→ 同一任务只能被抢到一次（`UPDATE … WHERE status='queued'` 的 `rowCount` 判定）。
3. `install.php` 的 MySQL 分支在「库存在但账号未授权」时的报错文案（已有三分支，建议加断言锁住）。
4. 静态资源：`public/` 下新增一个名字以 `assets` 开头的兄弟目录后，`/assets/../assets-x/f` 必须 404（**防止 §3.2 回归**）。

## 八、需确认（不确定的地方，未编造）

1. **⚠ A-3c 未解决**：`reap()` 的**负向对照**没有通过 —— 实测 `reaped=1 fresh_left=0`，
   即 `updated=now` 的任务也被回收了，而 cutoff 是 `now-10800`，按语义不该命中。
   我**未能在本会话内查清原因**。可能方向（**均未证实**）：PDO SQLite 返回 REAL 与比较参数的
   类型亲和性、`COALESCE` 与 REAL 列的比较行为、或探针里取 `microtime` 的时机。
   **不要把这项当成「已验证安全」** —— 它的实际含义是「`reap()` 可能比预期更激进」，
   正因如此 `A-3b`（真正要验的回收能力）是可信的，而**误杀正常任务的风险尚未排除**。
   该行已在验证脚本里保留为观察行（不参与通过/失败判定），原因写在脚本注释里。
2. **§3.2 的可达性**：前缀碰撞**当前不可利用** —— 能造成碰撞的目录必须位于
   `php/public/` 之内（如 `public/assets-evil`），而这样的目录**本来就能被 Web 直接访问**，
   不需要绕守卫。我按「守卫未达成其声明的职责」定级为**中危并修复**，
   但如果按「当前可利用性」定级，它是**低危**。请按你的定级口径确认。
3. **DDL 截断限制**：`INSERT OR REPLACE` → `Db::upsert` 后，`app_secrets` 的
   `created` 列会被一并刷新（原语义只更新 `value`）。对当前用途（验证码盐、队列游标）
   无影响，但**如需严格保持原语义**请告知。
