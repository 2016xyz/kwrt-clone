## 一、总体结论

### 总体风险等级：**中危**（修复后 → **低危**）

这个项目**已经被认真审计过并加固**（`params.py` / `safe_under` / `artifacts._safe_dir` 等处的注释都记录了「原先如何被绕过、现在如何修」）。
本轮没有发现未认证可达的 RCE、SQL 注入、路径穿越或支付绕过。
发现的问题集中在**口令存储的实现不一致**与**内存边界**两类。

### 最优先修复项

| 排序 | 项 | 为什么排第一 |
|---|---|---|
| 1 | `app/prefetch.py` 重复 `else:` → **整个应用无法 import** | 这不是安全问题而是**硬故障**：语法错误让 `uvicorn` 直接起不来。属于「语法/运行时错误」检查范围 |
| 2 | 三处口令写成**无盐 SHA-256** | 库一旦泄露，弱口令秒破；相同口令哈希相同，一撞一片。且与项目自身的 PBKDF2 设计自相矛盾 |
| 3 | `_LOGIN_FAILS` 无容量上限 | 未认证接口，可用海量随机用户名把内存灌爆 |
| 4 | 会话 Cookie 缺 `Secure` | 明文 HTTP 部署下会话令牌可被中间人截获 |

### 是否建议上线

**可以上线**，前提是本次 4 项修复已落地（均已修复并实测）。另需注意：

- `/admin/` 页面本身未鉴权（仅返回静态 HTML 外壳，所有数据接口都有 `require_admin`）——不构成越权，但建议一并加守卫
- 历史遗留的无盐哈希会在用户下次登录时自动升级；**从未登录过的老用户**建议手工批量重置

## 三、已确认安全的项（避免误报，逐条实测/逐行核对）

| 面 | 结论 | 依据 |
|---|---|---|
| **归档解包（tar/zip/7z）** | ✅ 安全 | `builder.extract()` 在 `extractall` **之前**逐条校验：绝对路径、`..` 分量、符号/硬链接目标、设备文件，并用 `_inside()` 做最终落点兜底。`bandit B202` 是**误报**（它不识别手工校验）。注释还记录了「原实现先解压后校验」的修复 |
| **路径穿越（数据集读取）** | ✅ 已修 | `GET /json/v1/{path:path}` 曾可 `../../../config.json` 读出配置（注释记录了实测），现用 `safe_under()`：`realpath` + 前缀校验，正确 |
| **路径穿越（构建物删除）** | ✅ 安全 | `artifacts._safe_dir()`：字符集白名单 `^[A-Za-z0-9_-]{1,64}$`（天然无 `/` 无 `.`）＋ `realpath` 前缀校验 ＋ 显式排除 `uploads` ＋ 必须是目录 |
| **路径穿越（构建入参）** | ✅ 安全 | `params.VERSION_RE` 无斜杠无 `..`；`TARGET_RE` 不允许连续分隔符（`..` 无法构成）；`PROFILE_RE` 首字符不能是 `.`；`files_path` 拒绝绝对路径/盘符/`..`/超深 |
| **命令注入** | ✅ 已修 | `params.sanitize()` 全字段白名单（注释记录了「target 里塞 `$()` 可命令执行」的修复）；`builder` 里 tar 管道用 `sh -c '脚本' sh "$1" "$2"` 传参，路径不进命令串 |
| **SQL 注入** | ✅ 无 | 全仓 `execute()` 无 f-string/`%`/`+` 拼接；`admin_builds` 的动态 WHERE 只拼固定串、值走 `?` |
| **支付（核心资金链路）** | ✅ 安全 | `pay.verify()` **fail-closed**（任何异常→False，空公钥也拒）；`alipay_notify` 先验签再查单、**核对金额**、未验签一律不发权益；`_sign_string` 按官方 rsaCheckV1 剔除规则实现 |
| **邮件头注入** | ✅ 安全（stdlib 兜住） | 实测：`msg["To"] = "a@b\r\nBcc: x"` → 抛 `HeaderParseError`；`Header("主题\r\nBcc: x")` → CRLF 被 RFC2047 编码，不产生注入头；`smtplib.sendmail` 自身也检查地址里的换行 |
| **邮件 HTML 模板** | ✅ 安全 | `render_html()` **默认全量 HTML 转义**，只有调用方在 `raw=()` 里显式列出的键才原样插入（目前只有已逐字段转义的 `rows`/`content`）；模板名白名单 `^[a-z0-9_]+\.html$` 杜绝路径穿越；模板带缓存与锁 |
| **会话固定** | ✅ 已修 | `api_login` 登录成功后先删旧令牌再签发全新 `secrets.token_hex(32)` |
| **令牌 / 密钥生成** | ✅ 安全 | 全仓统一用 `secrets`（`token_hex`/`token_urlsafe`）；下载令牌是 `hmac-sha256` 派生 + nonce |
| **口令校验** | ✅ 正确 | `hmac.compare_digest` 恒定时间比较；PBKDF2-SHA256 240 000 轮 + 每用户随机盐；历史无盐哈希兼容且登录后自动升级 |
| **构建入参边界** | ✅ 有上限 | 软件包数 ≤ 500、rootfs 64–4096 MB、包名字符集白名单、未知键丢弃 |
| **通用限速** | ✅ 有 | `_RATE` 滑动窗口 + `_RATE_MAX_KEYS=5000`（注册 / 重发验证邮件等入口）；登录有账号+IP 双维度锁定 |
| **状态变更 CSRF** | ✅ 基本可控 | 会话 Cookie `SameSite=lax`；状态变更全为 POST/PUT/DELETE（无 GET 改状态），跨站表单 POST 不会带 Cookie |

| **后台可以删除本地存储的构建物** | ✅ **已实现**：`app/artifacts.py` 提供 `delete`（按构建删产物，可选连记录一起删）/ `delete_orphans`（清理「磁盘有目录、DB 无记录」的孤儿目录），路由 `POST /api/v1/admin/artifact`，配套只读盘点 `GET /api/v1/admin/artifacts`（含占用统计、孤儿大小、上传目录占用） | **安全**。删除路径经 `_safe_dir()` 三重校验（字符集白名单 + `realpath` 前缀 + 排除 `uploads`），`shutil.rmtree` 后还会复核是否真的删掉并如实回报。悬空下载令牌会被一并作废 |
| **邮件使用 HTML 模板** | ✅ **已实现**：`app/templates/mail/*.html`（`layout.html` 外框 + `verify.html` / `build_ok.html` / `build_fail.html`），`mailer.render_html()` 默认全量转义 + `raw=()` 显式放行，`render_mail()` 套统一外框 | **安全**。模板名白名单防穿越、默认转义防注入、线程池 + 有界队列防线程堆积。另实测确认邮件头注入被 stdlib 兜住 |
