# 后台显示版本号 + 修掉「部署后静态资源不生效」

**需求原话**：「后台需要显示版本号，帮我在宝塔里面更新」

**结果**：需求已实现并上线验收；顺带挖出并修掉一个**更严重的**缺陷 ——
「代码部署上去了、用户端却还是旧页面」，根因是**三层缓存叠加**。

> 本报告不含任何明文凭据。

## 一、需求：后台显示版本号

### 1.1 现状

后台页头**本来就有**一个小徽标显示版本（`v1.0.1`），但总览页的「运行配置」面板里
只有构建引擎 / 构建后端 / 邮件通知 / 在线支付 / 下载链接有效期 / 默认插件配额 /
邮箱验证 —— **没有版本号**。而排障时第一件要问的恰恰就是「你现在跑的是哪一版」。

### 1.2 改动

| 文件 | 改动 |
|---|---|
| `web/admin.html` | 「运行配置」**首行**加「系统版本」，绑 `site.version` |

否则后台显示的版本号一旦不可信，排障会被带进沟里。

> 注：`web/admin.html` 是**纯静态 HTML**（Vue 前端），注释只能用 HTML 注释。

## 二、顺带挖出的严重缺陷：部署后静态资源不生效

### 2.1 现象

把「找回密码」入口写进 `login.js`、`login.html` 也一并部署到线上之后，
**用户端一直看不到入口**。用 `curl` 直接取线上文件，能拿到新内容 ——
但浏览器里就是不出现。

### 2.2 排查：一层一层隔离（每一步都是实测，不是推断）

| 步骤 | 手段 | 结果 |
|---|---|---|
| ① 磁盘 | 服务器上 `md5sum web/assets/js/login.js` | **12397B、md5 与本地逐位一致**（文件是对的） |
| ② 应用 | `curl 127.0.0.1:8443/assets/js/login.js`（绕过 nginx） | **12397B，新文件** ✓ |
| ③ nginx | `curl -H 'Host: op.2016xlx.cn' 127.0.0.1/assets/js/login.js` | **12021B，旧文件** ✗ ← 找到第一层 |
| ④ 配置 | 看反代配置 | 是**纯透传**，没有任何 `proxy_cache` 指令 —— 看着没问题 |
| ⑤ 全局 | `grep -rn proxy_cache /www/server/nginx/conf/` | **`proxy.conf:12: proxy_cache cache_one;`**，而 `nginx.conf:27` 直接 `include proxy.conf` —— **对全站所有 `proxy_pass` 生效** |
| ⑥ 参数 | 源站带一个全新的 `?cb=<时间戳>` 请求 | **12397B** ✓（说明 nginx 按完整 URL 做键，查询串能穿透它） |
| ⑦ CDN | 带一个**全新**的 `?v=xxx` 走线上域名 | **12021B，`Age: 9`** ✗ ← **EdgeOne 的缓存键忽略查询参数** |

**结论**：三层缓存叠加。

```
浏览器  ──►  EdgeOne（缓存键忽略查询串）  ──►  nginx（全局 proxy_cache）
                                                    ──►  uvicorn（内容正确）
```

应用给 `/assets/` 发的是 `Cache-Control: public, max-age=3600`，
nginx 与 CDN 都照抄 —— 于是**每次部署，静态资源最长一小时发不出去**。

这正是代码注释里早就警告过的情况（`RevalidatingStaticFiles` 的 docstring：
「若浏览器直接用本地缓存，用户升级后会拿到旧脚本，出现『服务端已修、页面仍旧』的幽灵问题」）——
只是当初只考虑了浏览器，没考虑**反代与 CDN** 这两层。

### 2.3 一个让问题无法自愈的细节

`asset_version()` 的默认值：

```python
v = str(SS.get("site.asset_version") or "").strip()
return v or "1"          # ← 管理员不填就恒为 "1"
```

PHP 侧更甚：回落到一个**从未被 `define` 过的常量** `KWRT_BUILD`，于是也恒为 `'1'`。

**即使当时就加了 `?v=`，版本号不变 → URL 不变 → 缓存照样命中。**
所以「版本号默认值必须内容派生」是这个修复不可分割的一半。

## 三、修法：路径式版本化

### 3.1 为什么不能用 `?v=`

实测（本报告 §2.2 步骤⑦）：**EdgeOne 的缓存键忽略查询参数**，全新的 `?v=` 仍命中旧缓存。
所以查询串只能穿透 nginx 与浏览器，**穿不过 CDN**。

只有**路径**变了，CDN 才认定是换了资源。

### 3.2 设计

```
/assets/_v/<ver>/js/login.js   →   web/assets/js/login.js
/static/_v/<ver>/...           →   web/static/...
/vendor/_v/<ver>/...           →   web/vendor/...
```

裸路径 `/assets/js/login.js` **仍然照常可用**，只是不再享受长缓存
（改为 `no-cache, must-revalidate`，让任何中间层都不敢把它锁住）。

### 3.3 两处关键改动

**① 版本号改为内容派生**

```python
def asset_signature() -> str:
    """对静态资源目录做内容签名：文件一改就变。

    取 (相对路径, 大小, mtime) 三元组的短哈希 —— 不读文件内容，
    但部署必然改变 mtime/size，所以够用且极便宜。结果缓存 30 秒。
    """
```

PHP 侧 `Net::assetSignature()` 同构实现，**两版算出的签名逐位相同**
（AV-1/AV-2 实测都是 `6f8179d960`）。

**② 缓存头判据从「是否配了 CDN」改成「这个 URL 是否版本化」**

```python
def asset_cache_headers(is_html: bool = False, versioned: bool = False) -> dict:
    if is_html or not versioned:
        return {"Cache-Control": "no-cache, must-revalidate"}
    return {"Cache-Control": "public, max-age=31536000, immutable", ...}
```

旧判据的漏洞正是本站的情形：CDN 是**外部**的（EdgeOne），应用根本不知道它存在，
`cdn_enabled()` 为假 → 发出可缓存的普通头 → 中间层照抄。
**正确的正确性条件只有一个：这个 URL 是不是版本化的。**

### 3.4 新增的文件转发入口必须自己扛住穿越

`/assets/_v/<ver>/<rest>` 是一个**新的文件转发入口**，等于多开了一个任意文件读取面。
三重收口：

1. 版本段白名单：`^[0-9A-Za-z._-]{1,40}$`（从入口杜绝 `../`）
2. 复用既有的 `builder._inside`（realpath + `commonpath`，不是 `startswith`）
3. PHP 侧同理，并沿用原有的 `Util::under`

并配了**负向对照**测试（用真实存在的 `users.db` 做靶）：

```
AV-11  负向对照：版本化路径不能目录穿越    ✓  试了 4 种，泄漏 无
AV-13  负向对照：PHP 版本化路径不能目录穿越  ✓  泄漏 无
```

## 六、遗留与建议（需要你在 EdgeOne 侧做一次配置）

现在的实现**不依赖** CDN 配置就已正确（路径变了就一定回源）。
但有一个代价值得你知道：

**EdgeOne 的缓存键忽略查询参数 ⇒ 它无法区分 `/a.js?v=1` 与 `/a.js?v=2`。**

对本轮修复没有影响（版本号已放进路径）。但如果你希望 CDN 的缓存命中率更好，
建议在 EdgeOne 里改一处：

| 位置 | 配置 | 建议 |
|---|---|---|
| 站点加速 → 缓存配置 → **缓存键** | 是否保留查询参数 | 改为**保留**（这样未来任何 `?x=` 类参数都能正确区分） |
| 缓存规则 | JS/CSS/图片的缓存行为 | 保持「遵循源站」即可 —— 源站已对**版本化路径**发 `immutable`、对**裸路径**发 `no-cache`，两边一致 |

另外两件此前提出、仍未处理的收尾项：

- 删除 `/root/kwrt-clone/data/INITIAL_ADMIN.txt` 与 `kwrt.env`（明文凭据，首次登录后即无必要）；
- 轮换宝塔面板口令并考虑开启 2FA。
