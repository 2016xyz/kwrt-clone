# 21 — 构建完成后下载「令牌格式错误」根因与修复

- **版本**：v1.0.4 → **v1.0.5**
- **影响面**：前台登录页「我的下载链接」、后台总览「最近构建」卡片
- **严重性**：高（功能不可用 —— 构建成功后拿不到固件）
- **状态**：已修复、已部署、已用真实浏览器复现验证

---

## 1. 现象

用户反馈：固件构建完成后，点下载链接得到

```
HTTP 410
下载链接不可用
令牌格式错误
```

## 2. 根因

`app/dl.py` 的 `list_for()` 末尾：

```python
if include_token:
    r["url"] = "/dl/t/" + r["token"]
else:
    r.pop("token", None)
    r["url"] = r.get("url") or ""      # ← 这里
```

`dl_tokens` 表**没有 `url` 列**（见 `dl.py::_init`），所以 `r.get("url")` 恒为 `None` →
`r["url"] = ""` 恒成立。

而 `/api/v1/downloads` 又显式把 `token` 抹掉：

```python
rows = dl.list_for(username=u["username"], include_expired=False, limit=200)  # include_token 默认 False
for r in rows:
    r.pop("token", None)
```

于是接口返回的每一行都是 **`url == ""` 且没有 `token`**。

前台 `web/login.html` 偏偏用不存在的字段拼链接：

```html
<a class="btn btn-sm btn-outline" :href="'/dl/t/' + d.token">下载</a>
```

`d.token` 是 `undefined` → 实际 href = **`/dl/t/undefined`**。

服务端 `dl.verify("undefined")`：

```python
if not token or "." not in token:
    return False, "令牌格式错误", None     # ← 命中
```

→ HTTP 410「下载链接不可用 / 令牌格式错误」。

**整条链路上没有任何一处报错**：后端日志干净、接口 200、页面正常渲染 —— 是一个纯"静默半成品"。

### 复现（线上实测）

```
$ curl -s -b ck http://127.0.0.1:8443/api/v1/downloads
{"count":2,"downloads":[{...,"filename":"sha256sums.txt",...,"url":""}]}   ← url 空、无 token

$ curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8443/dl/t/undefined
410
$ curl -s http://127.0.0.1:8443/dl/t/undefined | grep text-muted
<p class="text-muted">令牌格式错误</p>
```

## 3. 顺带暴露的两个字段缺失

同一张表上还有两个字段是**前端在用、后端从没返回过**：

| 前端字段 | 实际渲染结果 | 原因 |
|---|---|---|
| `d.remaining_hours` | 「undefined 小时」 | `list_for` 只给了 `remaining`（秒） |
| `d.size` | 「0 B」 | `dl_tokens` 表没有 size 列，也从没算过 |

后台「下载链接」页（`web/admin.html`）用的也是 `t.remaining_hours`，同样显示 undefined。

## 4. 修复

### 4.1 `app/dl.py` — `list_for()`

- 删掉伪造空串的 `r["url"] = r.get("url") or ""`；`include_token=False` 时**不再返回 url 键**（而不是返回一个空串骗调用方）。
- 新增 `remaining_hours`（秒向上取整；剩 1 分钟显示「1 小时」而不是「0 小时」）。
- 新增 `size`：从磁盘实取（`resolve_path()` + `os.path.getsize()`），文件已清理则 0 —— 不编造。

### 4.2 `app/main.py` — `/api/v1/downloads`

改用 `include_token=True`。理由：该 SQL 已经按 `username=<当前登录用户>` 过滤，返回的**本来就是用户自己的**令牌，页面必须拿到可点击的 url 才能下载；令牌原文仍不回传给前端，只给组装好的 `url`（并叠加 `_download_base()`，兼容配了外链域名的情况）。

> 注：原注释写的是「不回传令牌原文（防越权复制）」，但 `include_token=False` 的默认路径**根本无法产出 url**，等于把功能做死了。安全边界应靠 SQL 的 username 过滤保证，而不是靠不给 url。

### 4.3 `app/main.py` — `/api/v1/admin/overview`

补 `recent_builds`（按 `created` 倒序取 8 条）。

`web/assets/js/admin.js::loadOverview()` 里写的是 `recent_builds: d.recent_builds || []`，
但后端 return 的字典里从来没有这个键 → 后台首页「最近构建」卡片**永远显示「暂无构建记录」**，
哪怕库里明明有构建记录。属于同一类「接口有页面、页面没数据」的静默缺陷。

### 4.4 前端

- `web/login.html`：「我的下载链接」改用 `d.url`；链接失效时显示「链接不可用」而不是渲染一个死按钮；`:key` 改用 `d.url || (request_hash + '/' + filename)`（原来用 `d.token`，同样恒为 undefined）。
- `web/admin.html`：`remaining_hours` 加兜底，避免再出现 undefined。

### 4.5 PHP 版对齐

`php/src/Controllers/ApiController.php::downloads()` 原来直接回传原始行（有 `token`，
没有 `url` / `remaining_hours` / `size`）。已改为与 Python 版**同构**：
`downloads` 数组，每行含 `url` / `remaining_hours` / `size` / `expired` 等，
并保留 `tokens` 键作为旧结构兼容。

## 6. 教训（同类缺陷的通用形态）

这个 bug 的形态值得记一笔：**后端返回一个"看起来像字段"的空值，前端照常渲染，谁都不报错。**

- `list_for` 返回 `url: ""` 而不是干脆不给 —— 调用方无法区分「没权限」和「本来就是空」。
- 前端用 `d.token` 拼串，`undefined` 会**静默字符串化**成字面量 `"undefined"`，不抛异常。
- 结果是一个"双面都自洽、合起来不通"的死链。

防御手段：接口字段要么给对的值，要么不给键；前端拼接前判空并给出可见的降级文案
（本次改成 `v-if="d.url"` + 「链接不可用」，就是为了让下一次再坏时**页面可见**，而不是静默跳到 410）。

同类的扫描方式：把前端模板里所有 `obj.field` 取出来，跟后端所有字符串字面量取差集
（本次即用此法定位到 `recent_builds`）。
